# UX 設計

## 目標使用者

會用手機、會進路由器設定頁，但不知道什麼是 peer、AllowedIPs、NAT 的人。
（「自己家人」還是「做成產品給別人用」尚未決定，見 [decisions.md](decisions.md)。）

## 六條原則

1. **先檢測，再建議**：使用者不必選模式。頁面自己判斷網路環境，告訴他「你家可以用 A」或「你家要用 B」。
2. **用生活語言**：介面上不出現 peer、AllowedIPs、endpoint、exit node 這類詞（見下方對照表）。
3. **一鍵新增裝置**：只問一個問題——這台裝置叫什麼名字。
4. **私鑰不留在路由器上**：QR 只顯示一次，關掉後就無法再看；要重來就重新產生。
5. **改壞了能自己復原**：套用設定後若連不回頁面，自動回滾。
6. **頁面只開放給家裡的網路（LAN）**。

## 用語對照表

| 技術名詞 | 介面上的說法 |
|---|---|
| Peer / client | 裝置 |
| Add peer + generate keys | 新增一台手機／電腦 |
| AllowedIPs = 0.0.0.0/0, ::/0（full tunnel） | 出門時網路全部走家裡 |
| AllowedIPs = 家中 LAN 網段（split tunnel） | 只連家裡的設備 |
| Latest handshake | 最後在線時間（例：3 分鐘前在線） |
| Remove peer | 停用這台裝置 |
| Public IP / CGNAT / double NAT | 你家可以直接連回來／你家需要透過中繼才能連回來 |
| Endpoint / DDNS hostname | 家裡的地址 |
| Exit node（NetBird） | 出門時網路全部走家裡 |
| Setup key（NetBird） | 綁定碼 |

## 畫面草稿（手機優先）

### 畫面 0：第一次使用（環境檢測）

```
┌──────────────────────────┐
│ 🐸 Kaeru Tunnel           │
│                          │
│ 正在檢查你家的網路…        │
│ ✅ 路由器有連上網路         │
│ ✅ 你家有公網地址           │
│ ⚠️ 前面還有一台數據機        │
│                          │
│ 建議：直接連回家（WireGuard）│
│ 需要你到數據機開一個門 →     │
│ [ 看怎麼設定 ]  [ 下一步 ]   │
└──────────────────────────┘
```

檢測結果三種走向：

- **有公網 IP、沒有前置數據機** → 直接走 WireGuard 精靈
- **有公網 IP、前面有數據機（雙層 NAT）** → WireGuard，並引導到數據機開轉發埠（或改橋接）
- **CGNAT／沒有公網 IP** → 說明「你家需要透過中繼才能連回來」，引導到 NetBird（第二階段）

### 畫面 3：測試連線

引導使用者**關掉 Wi-Fi、改用行動網路**，打開 app 連線，頁面即時顯示「✅ 已收到這台裝置的連線」（偵測到第一次握手）。
這一步同時驗證了「從外面真的連得回來」，是檢測公網可達性最可靠的方法。

## 失敗時的說法

| 狀況 | 介面上的說法 |
|---|---|
| 一直沒有握手 | 還沒收到連線。請確認手機已關掉 Wi-Fi，並在 app 裡打開這個通道。 |
| 雙層 NAT 未轉發 | 你家前面的數據機擋住了連線，需要開一個門（UDP 51820）。[看怎麼設定] |
| 公網 IP 變了但 DDNS 沒更新 | 家裡的地址過期了，正在更新… |
| 套用設定後失聯 | 設定沒有成功，已自動還原成上一次可用的狀態。 |
